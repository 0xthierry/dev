# Omarchy 3.8.5 → Quattro: cutover checklist

This branch stages setup changes; publishing or fetching it does not upgrade a machine. Do not check it out over the active 3.x desktop before stock Quattro works: some live config files are symlinked into the checkout. The rehearsal used the installed `f4378f0` bridge, Omarchy 4.5.0-3 and Superwhisper 1.3.1-1. Recheck the release, bridge and package versions before using these results.

1. **Prepare for downtime.** Save open work, quiesce writers, refresh root/home snapshots, EFI backup and application-consistent database backups, and test representative restores. A root-only snapshot does not restore `/home` or `/boot`. The chosen same-SSD backups do not cover disk loss. Confirm access to rescue media, disk-unlock credentials and a local TTY independent of the desktop.
2. **Protect repo-owned symlinks.** Follow the [link audit and reversible protection procedure](omarchy-quattro-links.md). The official bridge can write through the Hyprland directory link and Ghostty config link into the checkout. Review Docker runtime/network/startup settings and workload restart policies separately; don't replace them blindly with package defaults.
3. **Run the official stable upgrade from the local console.** Update → Omarchy, then Update → Omarchy To Quattro. Review its output; decline the automatic reboot until package transactions are complete, the pacman database checks clean, migration state is clear, encrypted-root boot parameters/UKIs are correct, and SDDM and networking are ready. Bridge exit zero did not guarantee that all migrations succeeded.
4. **Keep dictation stock.** Don't install Voxtype, change the selected backend, or override Quattro shortcuts. If stock setup succeeds, do nothing. For the exact Superwhisper failure reproduced in the rehearsal, see below.
5. **Boot stock before deploying the overlay.** Verify encrypted-root unlock, graphical login, networking, lock/suspend, Docker workloads, physical monitors and GPU. Only then integrate the candidate and follow the [desktop and workspace instructions](../configs/hypr-quattro/README.md). Check clipboard, screen capture, screen sharing and a real dictation sample on the workstation. The VM could not verify the physical microphone or monitors.

## After conversion: prefer stock over carried-forward files

The migration tools above are for this one cutover, **not a second supported setup target**. Compare the installed user configuration with `/usr/share/omarchy/config/` before applying the [personal desktop settings](../configs/hypr-quattro/README.md). Files preserved by the official bridge can contain old choices even when this repo no longer sets them. Don't run a whole-directory refresh: it can also erase real edits.

- **Dictation:** Quattro owns the backend and shortcuts. The official `1793477875.sh` migration may append an explicitly commented F9 / Super+Ctrl+X block to `~/.config/hypr/bindings.lua`; those are compatibility keys, not fresh-install defaults. If present and you want only stock 4.x keys, back up that file and remove just the upstream-commented compatibility block after verifying it is unchanged. Do not remove other personal bindings or skip the migration.
- **Screen sharing: use Quattro's interactive picker** (`hyprland-preview-share-picker`), not the Sober observer. Fresh installations need no action. After the bridge, compare `~/.config/hypr/xdph.conf` with `/usr/share/omarchy/config/hypr/xdph.conf`. If the old Sober selection is the only customization and the file and its parent directories are no longer symlinks, run `omarchy refresh config hypr/xdph.conf` once as the desktop user. This backs up the old file and restores only the packaged portal config. Verify with `cmp ~/.config/hypr/xdph.conf /usr/share/omarchy/config/hypr/xdph.conf`. If unrelated settings are present, preserve them and change only the picker to the shipped value. In a fresh session, initiate a screen share and cancel the chooser to verify interactive selection without sharing a window. No full Hyprland reset or removal of the standalone helper is needed.
- **Lock and idle:** use stock Quattro screen and idle management. The previous idle file tracked old distribution defaults. Do not enrol a fingerprint or change PAM as part of this migration; verify password-based unlock locally before relying on the workstation unattended.
- **System policies:** Docker memory/build-cache limits, resource-pressure tuning, sysstat sampling and storage/build settings were deliberately added for this machine, not discovered in a copied desktop template (`9b896a3`, `2d9f08b`, `4ce3fcf`). Keep these separate from desktop defaults. Compare actual effective settings after the bridge; do not reapply storage flags, change encryption settings, or recreate workloads merely to test the desktop.

## Stock Superwhisper migration `1793667581.sh`

**Symptom:** after the bridge, `omarchy-migrate --pending` lists `1793667581.sh`; the stock installer reports `expected value at line 15 column 16`. In the rehearsal the *still-running old Hyprland* returned malformed JSON from `hyprctl -j binds`: `"keycode": XF86AudioRaiseVolume,` (unquoted value). The JSON preferences on disk were valid. `superwhisper shortcuts show` alone succeeded even though both native shortcut setters failed.

**Verified recovery, only if the diagnosis matches:**

1. Confirm `omarchy-default-dictation` reports `superwhisper`. From the affected graphical session run `hyprctl -j binds | python3 -m json.tool >/dev/null` to validate the binding data. Don't reset a profile or log out merely because a different error mentions JSON.
2. Save work and wait for the bridge/package transaction to finish. Establish an independent TTY as the same regular user first. Log out normally from the old graphical session; verify the old compositor is no longer running. Do not reboot yet.
3. From that user's home in the independent session, with the user systemd manager available and no stale graphical-session variables, run the full stock `omarchy-install-dictation-superwhisper --background`. Require a successful exit. Verify `superwhisper shortcuts show` reports native toggle `Ctrl+Alt+Space` and an empty hold shortcut; `systemctl --user is-active superwhisper.service` should say `active`.
4. Run the normal `omarchy-migrate`. For this release, `omarchy-migrate --pending` prints names and exits **0** when migrations remain; **empty output and exit 1** means none remain. Don't create a marker yourself: the package creates its `app/current` symlink early, so a migration retry alone can report success before the shortcut setters have finished.
5. Only after the other boot checks pass, reboot and unlock. If panel placement was deferred while no desktop was running, rerun the same stock installer from the new graphical session. Verify no pending migrations, the stock backend and daemon, and `hyprctl configerrors`.

In an independent encrypted VM replay, the full stock installer and queue finished on the same **old boot ID before reboot**. The first Quattro boot then reached SDDM graphical autologin on kernel `7.2.15-1-omarchy`, with valid compositor binding JSON, stock shortcuts, completed panel placement and clean package integrity. This is evidence for the recovery sequence, not a guarantee about other hardware, authentication configurations or later releases. Private machine backups, credential material, raw logs and disk images are deliberately not part of the repository.
