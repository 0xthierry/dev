# Source notes

This skill is an original synthesis of a direct reading of the pstack skills in `cursor/plugins` at commit `889ec4b68fa5aab0e867dad71ec3fdf386ae48f3`. The study covered 47 skill files, 30 Markdown reference files, and 23 playbooks. Existing local writing skills were not used as source material for this skill.

## Observations that shaped the guidance

- The [authoring playbook](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/poteto-mode/playbooks/authoring-a-skill.md) favors prose that changes a decision, selective explanations, and composition by reference.
- [Arena](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/arena/SKILL.md) and [Create a verification skill](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/create-verification-skill/SKILL.md) make actions, unacceptable shortcuts, and completion evidence concrete.
- [Boundary discipline](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/principle-boundary-discipline/SKILL.md) illustrates a compact principle. [Bro](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/bro/SKILL.md) illustrates a correction that needs no elaborate structure.
- The [How references](https://github.com/cursor/plugins/tree/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/how/references) separate evidence gathering from explanation. The [Why references](https://github.com/cursor/plugins/tree/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/why/references) make source limitations and confidence part of the output contract.
- [Guard the context window](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/principle-guard-the-context-window/SKILL.md) keeps frequently needed material inline rather than extracting everything.
- [Technical writing](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/technical-writing/SKILL.md) and [Unslop](https://github.com/cursor/plugins/blob/889ec4b68fa5aab0e867dad71ec3fdf386ae48f3/pstack/skills/unslop/SKILL.md) establish a preference for plain, concrete prose without sacrificing clarity to brevity.

## Limits of the synthesis

The source collection is not perfectly consistent. Some procedures are dense, terminology is sometimes figurative, and rules repeat across files. This skill adopts the useful patterns without treating those inconsistencies as requirements.

The source's model choices, mandatory delegation, autonomy policy, PR process, and Cursor-specific metadata are not part of a portable writing style. This skill does not import them. It also does not claim to reproduce Cursor's built-in `create-skill`, which was referenced but absent from the cloned repository.

The external standards named by pstack are influences, not conformance claims. This skill is not a complete implementation of Diátaxis, Google developer style, ASD-STE100, or the Global English Style Guide. Its examples were written for this skill and are not quotations or tested commands from the source project.
